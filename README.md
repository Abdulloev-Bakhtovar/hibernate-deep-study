# Hibernate Deep Study

Учебный репозиторий для последовательного изучения Hibernate ORM **изнутри**: от архитектуры и bootstrap до mapping-аннотаций, публичных API, SQL execution, транзакций, связей, fetching, кэшей и интеграции со Spring — только после завершения ядра Hibernate.

Репозиторий является единственным источником состояния обучения. Новый локальный AI-агент должен восстановить курс по Git-файлам и продолжить с текущего урока, не заставляя ученика заново пересказывать контекст.

## Текущее состояние

- PostgreSQL: база знаний пройдена.
- JDBC: пройден.
- JDBC Template (`JdbcTemplate`): пройден.
- Hibernate: **0% пройдено в рамках этого курса**. Предыдущие обсуждения и самодельные ORM-эксперименты не засчитываются как изученные темы.
- Текущий следующий урок: `H00 — ориентация в Hibernate и карта архитектуры`.
- Целевая версия: `Hibernate ORM 7.4.17.Final`, Java 17.

Смотри `state/HANDOFF.md` и `state/CURRENT.md`.

## Как начать

1. Распакуй архив в каталог будущего проекта.
2. Открой каталог в своей среде разработки и подключи его к локальному DeepSeek-агенту.
3. Убедись, что агент видит файлы проекта и может их читать/редактировать.
4. Передай агенту содержимое `prompts/START_NEW_AGENT.md` или просто попроси выполнить `/start`.
5. После занятия попроси `/checkpoint`, затем закоммить и отправь изменения в Git.

## Git: первая и последующие фиксации

```bash
git init
git add .
git commit -m "chore: initialize Hibernate deep study"
```

После настройки удалённого репозитория:

```bash
git remote add origin <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
git push -u origin main
```

После каждого учебного занятия:

```bash
git status
git add .
git commit -m "study: complete H00 Hibernate architecture orientation"
git push
```

Если новый агент запускается в другой рабочей среде, сначала сделай `git push`, а в новой среде — `git pull`. Незакоммиченные изменения остаются только в локальной рабочей копии и не гарантируют передачу следующему агенту.

## Принципы курса

- Сначала задача и механизм, потом API и аннотации.
- Сначала объясняем поведение на уровне Java/JDBC, затем прослеживаем, как это реализовано в настоящем Hibernate.
- Не выдавать готовое решение вместо практики: подсказки должны быть постепенными.
- Не считать тему пройденной по одному объяснению. Нужны код, проверка и объяснение ученика своими словами.
- Не подключать Spring до завершения ядра Hibernate.
- Все утверждения о внутренних классах и методах привязывать к версии `7.4.17.Final` и проверять по исходникам/официальной документации.

Подробнее: `docs/COURSE_RULES.md`, `docs/COURSE_ROADMAP.md`, `prompts/MASTER_PROMPT.md`.
